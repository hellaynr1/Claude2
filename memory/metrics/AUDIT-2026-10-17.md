## 2. Real flow: where things stall
1. **Approval layer has never been exercised.** Three separate runs will each open a PR every day → up to ~17 PRs/week to review: guaranteed rubber-stamping or backlog.
2. **Skills are decorative.** Behavior comes from CLAUDE.md + my reading files by hand; the 9 skills never load as skills.
3. **Dead rules:** "sync to Drive every change" and auto-save step 3/4 (`projects/second-brain.html` is a stale v2; the app's single source is `app/index.html`).
4. **Outputs pile up without outcomes:** content made but not posted; lessons built but nothing marked learned.
5. **Defects reach you on the phone** (Puter sign-in, mic): the smoke test can't see real-device behavior.

## 3. Proposed redesign (needs your yes: these are big changes)
From 14 systems + 9 skills + 3 scheduled runs → **5 workflows + 1 nightly run**.
| Keep as | Merges | Retire / archive |
|---|---|---|
| **Build** | build-app, ship-feature, bug-fix, full-stack-dev, reviewer (as its gate) | |
| **Research** | research-strategist, research-to-brain, competitor-watch | |
| **Content** | investedia-post + compliance-check (mandatory gate) | |
| **Learn** | learning-tracker, optimizer's teaching coach, Learn tab | |
| **Close-out** | personal-intelligence, sync-everything, auto-save rule | Drive-every-change → **weekly Drive export** (or retire Drive sync) |
| **Nightly run (1 trigger, 1 PR)** | daily optimizer + daily research + weekly content (Mondays) | the 2 extra triggers |
| | | start-of-day (merge into daily-plan), brand-kit (archive, one-off), video-notes/web-data stay as tools, not workflows |

**Contracts** (each workflow file gets): inputs · outputs · failure modes · approval point · kill criterion · metric + target.
**WIP limit:** the nightly run opens **at most 1 PR** and **skips** (spending nothing) while a previous PR is still unreviewed.
**Batch approval:** one PR per night with a checklist; Monday's includes the content.
